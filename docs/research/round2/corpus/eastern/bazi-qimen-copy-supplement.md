# 八字/奇门 补充文案素材 —— 六爻用神体系与断卦规则引擎设计要点

> 采集日期：2026-10-15
> 来源：GitHub Johnson-Jia/liuyao-divination（`references/02-用神取用.md`、`references/08-断卦步骤.md`、`references/11-六十四卦判辞.md`、`data/zhouyi.json`），仓库：https://github.com/Johnson-Jia/liuyao-divination
> 说明：本轮调研未发现明显优于现有 interpret-bazi.json（十神释义已具备基础层）与 BaziEval 方案（五行旺衰量化，见 docs/research/专项调研-用户指定项目.md）的八字补充文案；但发现**六爻纳甲的用神取用与断卦流程文档质量极高、规则化程度好**，与本项目奇门「用神聚焦」的设计同构，且六爻是二期「周易」板块最自然的扩展（起卦→装卦→断卦），故整录于此备用。

## 一、六爻规则引擎的分层（对齐本项目 core/ui 分层理念）

该仓库把六爻断卦拆为「机械层（程序算准）+ 推理层（解读文案）」，与本项目「确定性规则引擎 + interpret 语料」架构完全同构：

| 层 | 内容 | 对应本项目 |
|---|---|---|
| 排盘 | 装卦、纳甲、六亲、世应、六神 | core 模块（纯计算） |
| 状态判定 | 月建日辰定旺衰、动静暗动、月破日破、空亡、化进化退、三合六合、入墓 | core（确定性输出） |
| 解读 | 用神取用、有力无力判定、断卦八步流程 | interpret 语料 + 页面渲染 |

其 `data/zhouyi.json`（64 卦辞 + 385 爻辞，公有领域原文，按「乾为天」式卦名全称组织）可作 iching-64.json 的第二校验源。

## 二、用神取用表（问什么，取什么——与奇门用神聚焦同一 UX 模式）

- **自测吉凶/身体**：取「世爻」为用神。
- **父母长辈、师长、文书、房屋、车船**：取「父母爻」。
- **功名、官职、官司、丈夫、疾病（占病作官鬼看）**：取「官鬼爻」。
- **妻子、财物、器物**：取「妻财爻」。
- **兄弟、朋友、同辈、竞争**：取「兄弟爻」。
- **子女、晚辈、医药、僧道、六畜**：取「子孙爻」。

> 对本项目：六爻页可复用奇门页的「用神聚焦」交互——用户选问事类目 → 对应用神排到最前并标注。

## 三、断卦八步流程（解读引擎的确定性主干）

1. 定用神（按上表）；
2. 看用神旺衰（月建生扶为旺、克泄为衰；日辰同理，日辰为「六爻之主宰」）；
3. 看动爻与用神的关系（动来生扶为吉、动来克伤为凶）；
4. 看元神/忌神/仇神的**有力无力**（元神生用神、忌神克用神、仇神生忌神克元神）；
5. 看特殊状态：暗动、月破、日破、空亡（旬空）、化进化退、入墓；
6. 看卦局：三合局、六合卦、六冲卦、反吟伏吟、卦变生克墓绝；
7. 综合定吉凶：用神旺相有扶 → 事可成；休囚被克 → 事难成；空亡破散 → 应期另推；
8. 定应期（成事/败事的时间点：用神出空、出破、逢值逢合之期）。

> 该仓库把 1-7 全部程序化（排盘 CLI 自动判定暗动/化退/入墓/三合等），仅第 8 步与综合断语留给解释层——这正是本项目可复用的边界划法。

## 四、六十四卦判辞速查（data 素材）

`references/11-六十四卦判辞.md`（16KB）提供 64 卦「卦象 + 判曰」速查表（如「地泽临：二阳浸长，其势方兴；诸事渐进，宜谋不宜急」风格的四句判语），适合作为六爻解卦的「本卦总断」文案层，与 iching-64.json 的卦辞白话互补。已随本调研下载备份（/tmp 工作副本），如二期上六爻功能可整文件转换入库。

## 五、结论

- 八字十神/神煞：**现有语料 + BaziEval 量化方案已够 v2 用**，本轮不另采。
- 奇门解读：现有 interpret-qimen.json 门星神干释义完整，kinqimen（已调研）可补流派参数，无新增文案需求。
- **六爻是本轮最有价值的意外收获**：数据（zhouyi.json）+ 规则文档（11 册技法）+ 分层架构三齐全，若二期做「周易」板块，可按「时间卦/数字卦起卦 → 装卦纳甲 → 用神聚焦 → 八步断卦」实现，文案底稿已备。
