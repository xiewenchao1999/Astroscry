## 二、实现方案专题分析

### 1. 起卦算法（二期周易功能核心）

| 方法 | 规则 | 来源验证 |
|---|---|---|
| **时间卦（梅花易数标准式）** | (年支数+月+日) mod 8 定**上卦**，再加时辰数 mod 8 定**下卦**，三者总和 mod 6 定**动爻**；余 0 取 8（卦）/6（爻） | 通例；bazi-master 有实现但其变体（year+month+day mod 6 / hour*100+minute mod 6 取两动爻）**不采**，我们按标准梅花式实现 |
| **数字卦（梅花三数法）** | 两数各 mod 8 分定上下卦，和 mod 6 定动爻 | bazi-master `deriveChangingLinesFromNumbers`：`normalizeNumber` 把余 0 归化为模数值，实现干净可借 |
| **铜钱摇卦（六爻）** | 三枚铜钱掷六次：3 反=老阴(6)、3 正=老阳(9)、1反2正=少阴(8)、2反1正=少阳(7)；老阳老阴为动爻 | 通例 + Johnson-Jia 装卦文档；本项目已有 `crypto.getRandomValues` 可用 |
| **大衍筮法（蓍草）** | 50 取 1 太极 → 每爻「分二/挂一/揲四/归奇」三变 → 得 6/7/8/9，18 变成卦 | chengjun/iching wiki 步骤完整；网页版可做「快速简化版」（每爻按 6/7/8/9 传统概率 1/16:5/16:7/16:3/16 模拟），`ponytail:` 注明 |

### 2. 解卦规则引擎（变爻处理）

朱熹《易学启蒙》变爻规则（chengjun/iching 全文收录，可直接实现为确定性查表）：
- 0 爻动 → 本卦卦辞；1 爻动 → 本卦动爻爻辞；
- 2 爻动 → 两动爻爻辞，**以上爻为主**；3 爻动 → 本卦+变卦卦辞，**以本卦为主**；
- 4 爻动 → 变卦两不变爻爻辞，**以下爻为主**；5 爻动 → 变卦不变爻爻辞；
- 6 爻动 → 乾坤用「用九/用六」，余卦用变卦卦辞。

### 3. 签文/卦辞类 JSON 键设计（「卦/签 → 解曰/典故」定位模式）

三种实测范式：
- **AIzenHi（周易）**：单数组、每卦平铺所有字段（原文+白话+关系卦），`id`（文王卦序）即主键；起卦得 bits 后 `find(x => x.bits === computed)` 一次命中。适合我们（一次 fetch、一次遍历）。
- **iowi/guanyin（观音签）**：单数组按 `id` 1-100 排布；解读层不是独立文件而是每签内嵌 `interpretation{}` 对象，且**按签给键、非全键**——检索时需容忍缺键（`interp['家宅'] ?? '—'`）。键设计「原文键（英文）+ meta.keys 映射表」的形态已在我们落盘文件中保留。
- **freizl/yijing（npm）**：`id` 用六位二进制字符串作主键（"111111"→乾），起卦结果直接当 key 查——**bits 即主键**是最优雅的检索设计，我们的 core/iching 可采用（bits 常量序 = 自下而上）。

### 4. 一站式产品功能组织（bazi-master 产品地图，只看不抄 AI 路径）

八字 / 塔罗（单张/三张/凯尔特十字）/ 周易（数字+时间起卦）/ 星座（基础+每日+上升+配对）/ 紫微 / 合盘 synastry / 历史记录与收藏 / 多语言。对二期的启示：**「合盘 synastry」与「历史记录」是本项目尚未覆盖且纯前端可实现的两块**（我们已有 interpret-synastry.json 雏形）；其 AI 全走 LLM 解读层，与本项目「AI 仅 opt-in 润色」边界一致，架构理念互相印证。
