# ADR-003 · 零网络提示词出口（「复制提示词」）

**状态**：已接受（2026-10-15，用户指示按改造优化方案实施）　**决策人**：用户　**关联**：ADR-002（AI 解读层）、`docs/design/改造优化方案.md` D1/D2

## 决策问题

站点唯一的 AI 路径需要「自填端点 + 模型 + 密钥 + 勾选开启」四步（ADR-002）。行业趋势（36Kr：`#deepseek 算命` 话题 5608 万浏览）显示用户的主流路径是「拿一段 prompt 粘进自己已在用的大模型」。能否在不破坏「默认零外部请求」隐私不变量、不引入后端的前提下，给访客一条**零配置、零外联**的 AI 出口？

## 结论（先答问题）

**能**：新增「复制提示词」出口——站点只做 `navigator.clipboard` 本地写入，**不产生任何网络请求**，且不受 AI 开关约束（关闭态照常可用）。提示词由 `ui/ai-reading.mjs` 纯函数产出，与站内流式解读**共用同一份约束文本**，避免两条路径的解读质量漂移。

## 背景与力量（Forces）

| 力量 | 影响 |
|---|---|
| 隐私不变量（站点永不外呼） | 复制是**用户主动**把文本带出浏览器，站点自身零外联 → 不触碰不变量，只需在规范里显式登记该出口 |
| 无后端 / 无密钥托管 | 不能内置第三方 LLM；复制出口恰好不需要任何托管 |
| opt-in 路径门槛过高 | 只服务「技术型自用者」，放弃绝大多数访客；复制出口零门槛 |
| 解读质量一致性 | 若复制与站内各写一套 prompt，必然漂移且测试只覆盖一套 → 必须单一事实来源 |
| 用户隐私预期 | 复制内容含出生数据，用户可能并未意识到 → 复制文本**首行即为数据提示** |

## 被拒备选

| 方案 | 拒绝原因 |
|---|---|
| A. 内置第三方 LLM（默认开启） | 推翻隐私不变量与 ADR-002；无后端无法托管密钥 |
| B. 只保留 opt-in key 路径 | 覆盖率极低，等于放弃访客；不解决「门槛断层」 |
| C. 把提示词生成放进 `core/` | 违反「core 无 DOM/无网络、不碰 AI」的依赖方向，且破坏 no-network 测试的边界模型 |
| D. 复制出口也要求先开启 AI | 自相矛盾：复制本就不需要任何端点信息 |

## 决策

在 `ui/ai-reading.mjs`（唯一 AI 边界模块）内新增两个纯函数，并抽出共用约束常量：

```
ui/ai-reading.mjs
  ├── INTERPRET_RULES（导出常量：八条解读约束，含口径声明/先人话后术语/禁恐吓/高风险现实路径/免责）
  ├── systemFor(domain) ── 角色 + 数据来源说明 + INTERPRET_RULES + OUTPUT_SHAPE
  ├── buildMessages() ────────→ streamChat() ──→ 外部端点（opt-in，原路未改）
  └── buildPromptText() ──────→ 剪贴板（零网络，无需开启）

ui/ai-panel.mjs
  └── 「复制提示词」按钮：本页盘 → buildPromptText；无本页盘但有会话盘 → buildCombinedPromptText
      ├── 复制前段落 CLAUDE.md 隐私不变量「例外二」
      └── 失败降级：Clipboard API → execCommand → 落到输出区供手动全选
```

**七段式输出骨架**（抄开源方法论）：已确认信息 → 口径与默认项 → 盘面摘要 → 关键依据 → 核心判断 → 可执行建议 → 风险提醒与免责。

## 适应度函数（Fitness Functions）

| 性质 | 度量 | 阈值/规则 | 来源 | 失败响应 | 本地检查 |
|---|---|---|---|---|---|
| 默认态零外联 | 外部主机请求数 | 0（AI 关闭时，含点了「复制提示词」之后） | 浏览器网络面板 | 阻断合入 | `tests/no-network.test.mjs` |
| 复制出口不联网 | 提示词生成片段内 `fetch(` | 0 条 | 源码静态检查 | 阻断合入 | `tests/ai-prompt.test.mjs`（片段切片断言） |
| 与开关解耦 | 提示词片段内 `aiEnabled(` | 0 条 | 源码静态检查 | 阻断合入 | 同上 |
| 单一事实来源 | system 是否内联 `INTERPRET_RULES` | 两条出口都必须内联 | `npm test` | 修复模板 | `tests/ai-prompt.test.mjs` |
| 提示词完整性 | 输出必含 | 口径声明 + 排盘 JSON + 提问槽 + 免责 + 数据提示；长度 > 200 | `npm test` | 修复模板 | 同上 |
| 排盘确定性 | 同输入排盘输出 | 逐字节一致 | `npm test` | 修复排盘层 | 既有 `tests/*.test.mjs` |

## 后果

| 正面 | 负面 |
|---|---|
| 零门槛覆盖全部访客；仍保持站点零外部请求 | 提示词被粘到站外后产生的内容我们无法控制（缓解：约束文本写死「不得虚构未出现的信息」并要求标注不确定处） |
| 复用既有 `setAISource` 数据源，六个页面零改动即获得该能力 | 多一处模板需要维护（已通过共用常量收敛为一处） |
| opt-in 流式解读路径完全未改，回退成本 ≈ 0 | 剪贴板 API 在非安全上下文不可用（已做 execCommand 与手动复制两级降级） |

## 可逆性

删除 `buildPromptText` / `buildCombinedPromptText` 与面板按钮即完全回退（< 1 小时）。**重新评估的触发条件**：若用户反馈「粘过去答非所问」，说明提问框架需要重写；若发现复制出口的使用率远低于 opt-in，说明用户仍需更强的「一键直连」体验，届时重议内置 LLM 的备选 A。
