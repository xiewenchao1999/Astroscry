## 四、发现的问题与路由判定

### P-QA1（源码 bug → Engineer，Round 2 已修复关闭 ✅）dailyFortune 五维回补循环击穿 0-4 值域
- **位置**：`site/js/core/astro.mjs` `dailyFortune` 舍入回补段（约 L426-430）
- **现象**：`while (rsum < min)` 回补循环取**全维度最大者 +0.1**，不检查该维是否已达 4 上限；round1 舍入漂移使总和跌破 14 且最大维恰为 4.0 时，产出 **4.1**（> 4）
- **复现**：`dailyFortune(new Date(Date.UTC(2026, 9, 1, 4, 0, 0)), fortune-weights.json)` → leo（狮子）某维 = 4.1；对应测试 `tests/qa-supplement.test.mjs`「真实语料 fw × 连续 5 日全量扫描」
- **量化**：扫描 2025-01-01 → 2026-10-15 共 7836 星座日，**240 日（约 3.1%）** 出现 4.1（全部恰为 4.1，即单次回补步进）；越界值会直接渲染进 horoscope 页五维 meter 条（显示 4.1/4），违反 O04 验收「每维 0-4 分/维」
- **期望行为**：每维恒 ∈ [0,4] 且总和 ∈ [14,19]
- **修复**：commit d72d390——加分循环改为「在值 < 4 的维度中取最大者 +0.1」、减分循环对称防护「在值 > 0 的维度中取最小者」，两循环各带 null 防御 break；与 QA 建议一致，仅动回补段，纯函数确定性保持
- **Round 2 验证**：①全量 177/177 全绿（含原探针）；②两年 7836 星座日重扫：dims>4 = 0、dims<0 = 0、总和恒在 [14,19]；③原 4.1 案例点位（2026-10-01 leo）复测 dims = {total:4, love:4, career:1.7, money:2.6, health:1.7}，封顶正确 ✅
