# ADR-002 · AI 解读层接入评估（奇门等排盘的智能化解读）

**状态**：已接受（2026-10-14，用户拍板按本方案接入）　**决策人**：用户　**关联**：ADR-001

## 决策问题

排盘（奇门/八字/紫微/西占/塔罗）产出结构化数据后，能否接入 AI 大模型把数据进一步转化为个性化自然语言解读？若可行，如何在不破坏项目根基（纯静态、隐私、确定性规则引擎）的前提下改造？

## 结论（先答问题）

**可行，但只能作为「解读润色层」opt-in 接入，不能作为「卜算驱动」**。分界线：

- **卜算（排盘）**：永远由确定性规则引擎完成，AI 不得参与——这是 PRD 红线，也是产品可解释性的根基。AI 只消费排盘的**输出 JSON**。
- **解读**：现状是「规则 + 语料拼装」（interpret-*.json）。AI 可在此层之上叠加一层润色/综合，但必须 ①用户显式 opt-in ②自供 API key ③数据外发前明示。这需要先修订 CLAUDE.md 的隐私不变量（当前为「不得向任何外部主机发起网络请求」，无例外条款）。

## 背景与力量（Forces）

| 力量 | 影响 |
|---|---|
| 隐私不变量（生日/问题文本不出浏览器） | 云端 LLM 必然外发数据 → 只能做成 opt-in，不能默认开 |
| 纯静态无后端 | 无地方藏 API key；只能用户自填（localStorage）或用户自建代理，后者超出自用范围 |
| 禁 AI 作为卜算驱动 | AI 角色被限定在解读层；排盘输出的确定性与可测试性不受影响 |
| 「AI 感」的真实需求 | 用户要的是「说人话的个性化综合解读」，规则+语料可覆盖 80%，AI 补的是长尾组合的流畅表达 |
| 成本/依赖 | 云端 LLM 按量付费 + 供应商绑定；本地小模型零外发但代价极高（见被拒备选） |

## 被拒备选

| 方案 | 拒绝原因 |
|---|---|
| A. 浏览器内本地小模型（WebLLM/WASM，零外发） | 模型体积 0.5–2GB（违反静态站轻量前提）、低端设备跑不动、中文命理语料微调缺失导致解读质量大概率**不如现有规则语料**；为「合规」付出的体验代价不成比例。若未来端侧模型小而强，重新评估 |
| B. 自建后端代理 LLM（服务端持 key） | 直接推翻纯静态架构（ADR-001），引入运维/成本/数据落地三类负担；自用场景无此必要 |
| C. 维持现状不做 AI | 保守可行，但用户明确有此诉求；「完全不做」放弃了一个 opt-in 即可解锁的体验增量，不是最优解 |

## 决策

**主干不变（规则+语料），新增可选 AI 润色层，路线图化，本期不实施**：

```
core 排盘（确定性，不变）
   │ 结构化 JSON（宫位/门星神干/四柱…）
   ▼
规则解读层（现有 interpret-*.json，默认，离线可用）
   │ （仅当用户开启 AI 且已填 key）
   ▼
AI 润色层 ui/ai-reading.mjs（opt-in，独立模块，可整体删除）
   │ prompt = 角色限定 + 排盘 JSON + 用户问题；流式渲染；失败即降级回规则层
   ▼
渲染层
```

## 若拍板启用的改造清单（下一步）

1. **先改规范再改实践**：CLAUDE.md 隐私不变量增加 opt-in 例外条款（「除用户显式开启 AI 解读并自供 key 外，不得向外部主机发起请求；AI 仅限解读层，禁止参与排盘计算」），并同步更新 PRD 约束表述。
2. **设置面**：设置卡片——供应商/模型/baseURL/key（localStorage，明示「key 与排盘数据将发送至该服务」），默认关闭。
3. **模块边界**：`ui/ai-reading.mjs` 单文件模块，接口 `synthesize(structured, question, config) → AsyncIterable<string>`；core 与 data 层**禁止 import 它**（依赖方向单向）。
4. **Prompt 契约**：system 限定「只解读给定数据、不得虚构排盘信息、不替用户做重大决策」；结构化数据以 JSON 注入；输出流式展示。
5. **降级路径**：无 key / 请求失败 / 响应异常 → 静默回退规则解读并提示原因；AI 层任何故障不得影响排盘主流程。
6. **测试**：no-network 测试为 AI 模块开 opt-in 白名单（关闭态断言零请求）；新增「core 不 import ai-reading」依赖方向断言。

## 适应度函数（Fitness Functions）

| 性质 | 度量 | 阈值/规则 | 来源 | 失败响应 | 本地检查 |
|---|---|---|---|---|---|
| 隐私（默认态） | 外部主机请求数 | 0（AI 关闭时） | 浏览器网络面板 / 测试 | 阻断合入 | tests/no-network（扩展 AI 关闭态用例） |
| AI 不参与卜算 | core→ai 依赖 | 0 条 import | 静态检查 | 阻断合入 | tests 增加源码 grep 断言 |
| 确定性排盘 | 同输入排盘输出 | 逐字节一致 | npm test | 修复排盘层 | tests/*.test.mjs |
| 降级可用 | 无 key 时解读完整度 | 规则层 100% 可用 | 手测 | 修复降级路径 | 各页主流程回归 |

## 后果

| 正面 | 负面 |
|---|---|
| 长尾组合获得流畅、个性化的综合解读 | 引入外部依赖与按量成本；数据外发（opt-in 前提下） |
| 排盘可解释性根基不受影响（AI 只读输出） | 多一条需要维护的模块与 prompt 契约 |
| 模块独立可整体删除，回退成本 ≤1 天 | key 存 localStorage 有本机泄露面（自用可接受，需明示） |

## 可逆性

opt-in 独立模块，删除 `ui/ai-reading.mjs` + 设置项即完全回退（一天内）。**重新评估的触发条件**：用户明确要求启用该功能；或端侧模型成熟到 100MB 级可跑高质量中文解读（届时备选 A 可翻案）。

## 责任

决策：用户。实现与检查：本地 npm test + 各页浏览器回归（现有流程不变）。
