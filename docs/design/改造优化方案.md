# 星卜 Astroscry · 改造优化方案

> 制定日期：2026-10-15 · 依据：`docs/research/开源项目调研-提示词与语料.md` + 当前代码仓库盘点
> 本文件是**决策记录 + 分期计划**；实施过程中的细节以代码与测试为准。

---

## 一、决策问题

星卜已完成 v1 全流程闭环（6 个排盘页 + 规则语料解读 + opt-in AI 悬浮栏），但存在两个用户侧问题：

1. **门槛断层**：站点唯一的 AI 路径需要「自填端点 + 模型 + 密钥 + 勾选开启」四步，而行业趋势显示用户的主流路径是「复制一段提示词粘进自己已在用的大模型」。我们当前**没有任何把盘面变成可带走文本的出口**。
2. **内容深度不均**：塔罗只有「牌义 + 结构 + 五段式」，缺按提问语境的解读与神秘学对应；西占只有逐对相位，缺图形识别；紫微的运限引擎已具备却只在首页露过一次。

**本次要回答**：在不破坏「纯静态 + 无构建 + 隐私默认零外部请求 + 确定性卜算」四条硬约束的前提下，如何改造才能让更多访客用得下去、看得更懂？

---

## 二、目标 / 非目标 / 约束

| 类别 | 内容 |
|---|---|
| 目标 | ① 让**不配置任何东西**的访客也能拿到一份可带走的个性化解读；② 补齐三处最明显的语料深度缺口（塔罗语境 / 西占图形 / 紫微运限）；③ 让解读带上「口径与依据」，提高可信度 |
| 非目标 | 不做账号、不做后端、不做社交分享、不做付费；不引入任何新依赖；不改不得动排盘算法口径 |
| 硬约束 | ① **默认零外部请求**（含新功能：复制提示词是纯本地剪贴板写入，不产生任何网络请求）② 无构建步骤 ③ `core/` 纯计算、无 DOM 无网络 ④ AI 相关文案/字面量只能存在于 `ui/ai-*.mjs`（no-network 测试的既有边界） |

## 三、系统现状图（改造前）

```
site/data/*.json（interpret-*.json 语料、tarot.json 牌义、权重表…）
        ▲ 同源 fetch
        │
core/*.mjs  纯计算（bazi/ziwei/astro/tarot/qimen + *-reading 规则拼装）
        ▲
ui/*.mjs    layout / birth-profile / wheel / motion / ai-settings / ai-reading / ai-panel
        ▲
pages/*.mjs 表单 → core → 渲染；排盘成功后 setAISource(domain, structured)
        ▲
ai-panel.mjs  悬浮栏：仅当 aiEnabled() 为真才发起外部请求（opt-in）
```

**边界现状**：`ai-reading.mjs` 是唯一被允许「把排盘数据组织成会离开浏览器文本」的模块（ADR-002）。它有两种出口形态：
- 现有出口：`messages` 数组 → `streamChat()` → 外部端点（需 opt-in + key）。
- **缺失出口**：同一份材料 → 可**复制带走**的纯文本（用户自己粘到别处）。这是本次改造的核心切入点。

## 四、决策

### D1（P0）新增「零网络提示词出口」：复制提示词

**决策**：在 `ui/ai-reading.mjs` 增加纯函数 `buildPromptText(domain, structured, question)`（及跨页版 `buildCombinedPromptText(sources, question)`），返回一份可粘贴文本；在 `ui/ai-panel.mjs` 增加「复制提示词」按钮。

| 力量（Forces） | 说明 |
|---|---|
| 用户路径已迁移 | 36Kr：`#deepseek 算命` 话题 5608 万浏览；用户找 prompt 粘贴而非装 App |
| 同行都提供该出口 | `mingyu` 的 `/prompt` 任务书、`astroway-mcp`、`Horosa` 均可产出提示词文本 |
| 我们唯一的 AI 出口门槛过高 | 自供 key 四步配置，对「只想看看」的访客即流失 |
| 隐私不变量 | 复制是**用户主动**把文本带走，站点零外部请求；不改变默认态 |

**被拒备选**

| 方案 | 拒绝原因 |
|---|---|
| A. 内置第三方 LLM（默认开） | 直接推翻隐私不变量与 ADR-002，且无后端无法托管 key |
| B. 只保留 opt-in key 路径 | 覆盖率极低，等于放弃绝大多数访客 |
| C. 把提示词生成放到 `core/` | 违反「core 无 DOM/无网络/不碰 AI」的依赖方向与 no-network 边界 |

**决策图（改造后）**

```
ai-reading.mjs（唯一 AI 边界模块，仍由 no-network 测试的白名单管着）
   ├── buildMessages() ──→ streamChat() ──→ 外部端点（opt-in，原路不变）
   └── buildPromptText() ──→ 剪贴板（新增，零网络，无需开启）

ai-panel.mjs：面板底部新增「复制提示词」按钮
   ├── 未开启 AI：照样可用（这是关键——不与 aiEnabled() 绑定）
   └── 复制成功 → 按钮文案短暂变为「已复制 ✓」（motion/reduced-motion 友好，纯文案变化）
```

**后果**

| 正面 | 负面 |
|---|---|
| 零门槛覆盖 100% 访客；仍零外部请求 | 提示词可能被粘到大模型后产生站外幻觉内容，我们无法控制（已在文本里写死约束并要求 AI 标注不确定处） |
| 复用现有 `setAISource` 数据源，6 个页面零改动即获得该能力 | 多一个需要维护的模板（与 `GENERIC_RULES` 同源，避免两套） |
| opt-in 流式解读路径完全不变，回退成本 ≈ 0 | — |

**可逆性**：删除 `buildPromptText` 与按钮即回退（< 1 小时）。**重新评估触发条件**：若发现用户大量粘贴并反馈「答非所问」，说明模板的提问框架需要重写。

**责任**：实现与检查 = 本地 `npm test`（新增断言）+ 各页浏览器回归。

### D2（P0）提示词骨架升级为七段式 + 口径声明

**决策**：把 `GENERIC_RULES` 升级为带**输出结构要求**的约束块，抄 `Numerologist_skills` 的五条：

1. **先声明口径**（体系 / 流派 / 默认项 / 边界提醒）；
2. **已确认信息复述**；
3. 盘面摘要只说关键结论，不堆术语；
4. **先人话后术语**，术语首次出现简要解释；
5. **不展示完整推理链**；
6. 结论明确但语气平和，**禁恐吓式语言**（必败/必死/无救）；
7. **高风险主题必须附现实专业路径**，末尾固定免责声明。

同一段文本同时用于「站内流式解读」与「复制提示词」——**单一事实来源，避免两条路径的解读质量不一致**。

**被拒备选**：给复制出口和流式出口各写一套 prompt——两套必然漂移，且测试只能覆盖一套。拒绝。

### D3（P1）塔罗：按「提问语境」解读

**决策**：塔罗页增加「问事主题」选择（综合 / 感情 / 事业 / 财运 / 健康 / 心灵），语料新增 `topicLens`（6 主题 × label·askHint·focus·exit），综合解读按主题改写「聚焦句」与「落地动作」；主题选择器由语料驱动（键顺序即选项顺序），切换时同步改写提问框提示。

**被拒备选**

| 方案 | 拒绝原因 |
|---|---|
| A. 按 Tarotoo 做「78 牌 × 4 语境 × 2 正逆」逐牌语境释义 | 内容量大、易错，且与「提问语境」正交度低——同一张牌在感情/事业下的差异，远小于「框架措辞」带来的差异。选 6 主题框架，性价比更高（ponytail：上限是「同牌跨语境共用一条牌义」，升级路径 = 后续按需补 `cards[].domains`） |
| B. 补 `tarot.json` 逐牌元素·行星·星座对应（原计划） | **实施时放弃**：这是 74 条左右的黄金黎明对应表（22 大阿卡纳 + 36 数字牌旬度 + 16 宫廷牌区间），流派分歧真实存在（Strength/Justice 编号、天王星 vs 风元素），出错成本高而用户可感知价值仅是一行元数据。YAGNI → 用已有的「花色→元素」表即可，不引入易错的新权威断言 |

### D4（P1）西占：相位图形识别

**决策**：`astro.mjs` 新增 `detectPatterns(planets, aspects)`，识别 **大十字 / T 三角 / 大三角 / 群星**（实现口径见下），优先级按此顺序排序，每类只取一个代表、最多 3 类；`interpret-natal.json` 加 `patterns` 语料；`natal-reading.mjs` 输出 `patterns` 并在页面上作为「这张盘的骨架」呈现。

**实现口径（保守，宁缺勿错）**：大十字 = 两组互不相交的对分轴之间四刑齐备；T 三角 = 一条对分轴 + 第三颗对两端皆刑（已计入大十字的组合不再重复报告）；大三角 = 三颗两两成拱（120° 步进必然同元素，元素自动一致）；群星 = 同星座 ≥3 **且含至少一颗个人行星**（否则木土天海冥同座是世代现象，人人都有，不构成个人配置）。

**被拒备选**：只列逐对相位（现状）——用户看不出「盘的整体形状」，而这正是 Asteria/AstroChart 类产品最抓眼的产出。另拒「同宫群星」写法：整宫制下落宫由宫头星座决定，同宫与同座的判定会重叠，只留同座一种口径更不容易自相矛盾。

### D5（P1）紫微：运限上本命页

**决策**：紫微本命页新增「运限」卡，复用已存在的 `ziweiHoroscope(castInput, dateISO)`，展示当前**大限**（虚岁区间 + 限内命宫落在本命盘哪一宫 + 四化）与**流年**（干支 + 虚岁 + 流年命宫落宫 + 四化，四化按 禄/权/科/忌 顺序渲染成「星＋化」对）；同一份运限数据也传给 AI 数据源。

**已确认无需改动**：主星**亮度**（庙旺得利平不陷）早已在十二宫格内呈现（`palaceCell` 的 `(s.brightness)`），原计划的「补亮度呈现」属于重复建设，取消。

**被拒备选**：不做——引擎数据已算出却只出现在首页一行，是**已付费未使用的资产**。

### D6（P2）「口径与依据」卡片（**已修订：改为一处集中，不做七页重复**）

**原计划**：抽公共组件 `reading-notes`（折叠卡），把每页的**体系 / 流派 / 默认项 / 已知边界**列出来（内容进 `interpret-*.json` 的 `notes` 键）。

**修订后决策**：把七个体系的**取法 / 默认项 / 已知边界**汇总成 `about.html` 的一张<table>「各体系口径」卡（并在首页能力总览里以「关于与依据」直接可点），另加一张卡说明「AI 解读的两种用法」与其隐私语义。

**修订理由**：原方案要在 7 个页面各插一份折叠卡 + 7 份语料，是把同一份事实复制七遍（违反 DRY，且七处必然漂移）。集中一处、从首页直达，用户心智上就是「依据页」，成本约为原方案的 1/7；一次性看清全部体系的口径，也比较符合「想核对依据」时的真实意图。D6 的来源诉求（先声明口径 + 出处可追溯）由「集中页 + AI 提示词内的口径声明要求」两条路径共同满足。

**若日后要拆**：`about.html` 的这张表就是唯一事实来源，拆成每页折叠卡只需把它按体系切分到各 `interpret-*.json`。

## 七、风险登记

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 复制提示词让用户把**生日信息**带到第三方大模型 | 高（本就是本功能目的） | 隐私预期变化 | 复制内容**首行即写明**「以下含你的出生数据，粘贴前请确认目标平台的可信度」；设置卡与关于页同步说明此出口 |
| 引入大模型品牌词触发既有 no-network 断言 | 中 | 阻断合测 | 文案保持中性（「任意大模型 / 你常用的对话工具」），品牌词只允许出现在 `ui/ai-*.mjs` |
| 塔罗主题语料与其 5 段结构错配导致拼装出病句 | 中 | 阅读体验 | 主题层只**替换框架句**，不触碰原有 5 段骨架；回归时逐主题切一遍 |
| `detectPatterns` 误报（几何判定不严） | 中 | 解读失真 | 用容许度阈值 + 基准盘断言；无匹配时**不渲染**卡片，宁缺勿错 |
| 紫微运限对象形状与页面假设不符 | 中 | 显示 undefined | 复用首页已验证的 `ziweiHoroscope` 消费方式；防御式取值 |
| 浏览器模块缓存掩盖新代码（本项目已知坑，已 3 次） | 高 | 回归误报 | 回归前 `fetch(url,{cache:'reload'})` 逐模块刷 + 硬刷新 |

### 回归中发现的两点（已记录，未改代码）

1. **剪贴板写入在自动化环境被拒**：`navigator.clipboard.writeText` 与 `document.execCommand('copy')` 在该浏览器环境均不可用 → 实际走了**第三级降级**（把提示词全文显示在输出区供手动全选复制）。降级路径按设计工作，提示词内容完整无误；**成功态「已复制 ✓」在本环境无法观察到**，需在真实 https 站点由用户手测确认。
2. **扇形牌堆的点击无法由自动化工具驱动**：自动化 harness 的坐标点击打不到旋转/重叠的扇形牌（改走键盘 Tab+Enter 后抽牌/翻牌流程完全正常）。这是**工具限制而非产品缺陷**——键盘路径可用性由此得到额外验证；同时印证了既有记忆里「中心牌可点、键盘可达」的备注。
